\title{Voxd Voice Agent Provisioning Lifecycle}
\maketitle

\section{Scope}

Voxd provisions ElevenLabs resources for the voice call: one agent at a
time that new calls use, plus the resources that agent owns. A resource is
a client tool today; the same lifecycle covers any other kind an agent may
own, such as an MCP server or a stored secret, because the rules do not
depend on the kind. The model covers what the registration file records,
what exists remotely, and the gap between them that a lost file, a crash, a
dashboard deletion or a hand-edited file leaves behind.

Replacing the configuration builds a new agent beside the active one and
swaps it in. The daemon allows one call at a time, so no call rides a
replaced agent when the swap happens, and the model has no call state.
Voxd never writes to an agent it did not create in the current build. Its
one write to an existing agent is the attach step, applied to an agent that
is still being built, before any call can reach it.

\texttt{marked} holds the remote agents whose name carries voxd's marker and
this host. A marker is a name, so anyone can create a foreign agent that
carries one; no automatic path treats \texttt{marked} as proof of
ownership. Automatic deletion applies only to ids the registration file
names, and only after the remote agent's marker is read back. A sweep of
marked agents the file does not record is a person's act.

\begin{zed}
  [AGENTID, RESID]
\end{zed}

\begin{schema}{Lifecycle}
  active, building, retired, proven, complete : \power AGENTID \\
  fileOwned : AGENTID \pfun \power RESID \\
  remoteAgents, marked : \power AGENTID \\
  remoteRes : \power RESID \\
  attached : AGENTID \pfun \power RESID
\where
  \# active \leq 1 \land \# building \leq 1 \\
  active \cap building = \emptyset \\
  active \cap retired = \emptyset \\
  building \cap retired = \emptyset \\
  \dom fileOwned = active \cup building \cup retired \\
  proven \subseteq active \cup retired \\
  marked \subseteq remoteAgents \\
  \dom attached = marked \\
  complete \subseteq marked \\
  \bigcup (\ran attached) \subseteq remoteRes \\
  \forall a, b : \dom attached \spot a \neq b \implies
    attached~a \cap attached~b = \emptyset
\end{schema}

\texttt{active} is the agent new calls use, \texttt{building} the one being
provisioned, \texttt{retired} the replaced agents awaiting deletion, and
\texttt{proven} the recorded agents on which a call setup has succeeded.
\texttt{fileOwned} is the registration file's map from each recorded agent
to the resources recorded for it. \texttt{attached} is the remote truth: the
resources each marked agent actually lists. \texttt{complete} holds the
agents whose recorded resources are all attached. The registration file is
absent exactly when \texttt{fileOwned} is empty.

\begin{schema}{InitLifecycle}
  Lifecycle'
\where
  active' = \emptyset \land building' = \emptyset \land retired' = \emptyset \\
  proven' = \emptyset \land complete' = \emptyset \\
  fileOwned' = \emptyset \\
  remoteAgents' = \emptyset \land marked' = \emptyset \\
  remoteRes' = \emptyset \land attached' = \emptyset
\end{schema}

\section{Building and swapping}

The agent is created first, with the marker, so a marked agent exists before
any resource does. Each resource is created and recorded for it, then one
write attaches all of them to the agent. An agent that is not complete is
never published.

\begin{schema}{BeginBuild}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  building = \emptyset \land agent? \notin remoteAgents \\
  building' = \{agent?\} \\
  remoteAgents' = remoteAgents \cup \{agent?\} \\
  marked' = marked \cup \{agent?\} \\
  attached' = attached \cup \{agent? \mapsto \emptyset\} \\
  fileOwned' = fileOwned \cup \{agent? \mapsto \emptyset\} \\
  active' = active \land retired' = retired \\
  proven' = proven \land complete' = complete \\
  remoteRes' = remoteRes
\end{schema}

\begin{schema}{CreateResource}
  \Delta Lifecycle \\
  agent? : AGENTID \\
  res? : RESID
\where
  agent? \in building \cap marked \land res? \notin remoteRes \\
  remoteRes' = remoteRes \cup \{res?\} \\
  fileOwned' = fileOwned \oplus
    \{agent? \mapsto fileOwned~agent? \cup \{res?\}\} \\
  active' = active \land building' = building \land retired' = retired \\
  proven' = proven \land complete' = complete \\
  remoteAgents' = remoteAgents \land marked' = marked \\
  attached' = attached
\end{schema}

\begin{schema}{AttachResources}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  agent? \in building \cap marked \\
  fileOwned~agent? \subseteq remoteRes \\
  attached' = attached \oplus \{agent? \mapsto fileOwned~agent?\} \\
  complete' = complete \cup \{agent?\} \\
  active' = active \land building' = building \land retired' = retired \\
  proven' = proven \land fileOwned' = fileOwned \\
  remoteAgents' = remoteAgents \land marked' = marked \\
  remoteRes' = remoteRes
\end{schema}

\begin{schema}{Publish}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  agent? \in building \cap complete \\
  building' = \emptyset \land active' = \{agent?\} \\
  retired' = retired \cup active \\
  proven' = proven \land complete' = complete \\
  fileOwned' = fileOwned \\
  remoteAgents' = remoteAgents \land marked' = marked \\
  remoteRes' = remoteRes \land attached' = attached
\end{schema}

\texttt{Prove} records that a call setup succeeded on the active agent. A
replaced agent is deleted only while the active one is proven; if the
active agent fails its first setup, the previous proven agent is promoted.

\begin{schema}{Prove}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  agent? \in active \\
  proven' = proven \cup \{agent?\} \\
  active' = active \land building' = building \land retired' = retired \\
  complete' = complete \land fileOwned' = fileOwned \\
  remoteAgents' = remoteAgents \land marked' = marked \\
  remoteRes' = remoteRes \land attached' = attached
\end{schema}

\begin{schema}{Promote}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  active = \emptyset \land agent? \in retired \cap proven \\
  active' = \{agent?\} \land retired' = retired \setminus \{agent?\} \\
  building' = building \land proven' = proven \land complete' = complete \\
  fileOwned' = fileOwned \\
  remoteAgents' = remoteAgents \land marked' = marked \\
  remoteRes' = remoteRes \land attached' = attached
\end{schema}

\section{Deletion}

Every automatic deletion starts from an id the registration file names and
reads the remote agent back first. \texttt{DeleteMarked} applies only when
the remote agent carries the marker; \texttt{DeleteGone} only when the
remote agent no longer exists. No schema applies to a remote agent that
exists and is not marked, so a file naming a foreign agent deletes nothing.
Deleting a marked agent deletes the resources the agent itself lists, which
is the remote truth, never a resource id taken from the file alone.

\begin{schema}{DeleteMarked}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  agent? \in active \cup building \cup retired \land agent? \in marked \\
  active' = active \setminus \{agent?\} \\
  building' = building \setminus \{agent?\} \\
  retired' = retired \setminus \{agent?\} \\
  proven' = proven \setminus \{agent?\} \\
  complete' = complete \setminus \{agent?\} \\
  fileOwned' = \{agent?\} \ndres fileOwned \\
  remoteAgents' = remoteAgents \setminus \{agent?\} \\
  marked' = marked \setminus \{agent?\} \\
  remoteRes' = remoteRes \setminus attached~agent? \\
  attached' = \{agent?\} \ndres attached
\end{schema}

\begin{schema}{RetireGate}
  Lifecycle \\
  agent? : AGENTID
\where
  agent? \in retired \\
  active \neq \emptyset \land active \subseteq proven
\end{schema}

\texttt{DeleteRetired} is the deletion of a replaced agent: the same effect
as \texttt{DeleteMarked}, allowed only while the active agent is proven.

\begin{zed}
  DeleteRetired \defs DeleteMarked \land RetireGate
\end{zed}

\begin{schema}{DeleteGone}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  agent? \in active \cup building \cup retired \land agent? \notin remoteAgents \\
  active' = active \setminus \{agent?\} \\
  building' = building \setminus \{agent?\} \\
  retired' = retired \setminus \{agent?\} \\
  proven' = proven \setminus \{agent?\} \\
  fileOwned' = \{agent?\} \ndres fileOwned \\
  remoteRes' = remoteRes \setminus
    (fileOwned~agent? \setminus \bigcup (\ran attached)) \\
  complete' = complete \land remoteAgents' = remoteAgents \\
  marked' = marked \land attached' = attached
\end{schema}

\section{What can happen outside voxd}

\begin{schema}{RemoteDelete}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  agent? \in marked \\
  remoteAgents' = remoteAgents \setminus \{agent?\} \\
  marked' = marked \setminus \{agent?\} \\
  complete' = complete \setminus \{agent?\} \\
  attached' = \{agent?\} \ndres attached \\
  active' = active \land building' = building \land retired' = retired \\
  proven' = proven \land fileOwned' = fileOwned \\
  remoteRes' = remoteRes
\end{schema}

\begin{schema}{ForeignAgent}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  agent? \notin remoteAgents \\
  remoteAgents' = remoteAgents \cup \{agent?\} \\
  marked' = marked \land attached' = attached \\
  active' = active \land building' = building \land retired' = retired \\
  proven' = proven \land complete' = complete \land fileOwned' = fileOwned \\
  remoteRes' = remoteRes
\end{schema}

\begin{schema}{TamperFile}
  \Delta Lifecycle \\
  foreign? : AGENTID
\where
  foreign? \in remoteAgents \setminus marked \\
  active' = \{foreign?\} \land building' = \emptyset \land retired' = \emptyset \\
  proven' = \emptyset \\
  fileOwned' = \{foreign? \mapsto \emptyset\} \\
  complete' = complete \\
  remoteAgents' = remoteAgents \land marked' = marked \\
  remoteRes' = remoteRes \land attached' = attached
\end{schema}

\section{Lost registration and crashes}

\begin{schema}{LoseFile}
  \Delta Lifecycle
\where
  active' = \emptyset \land building' = \emptyset \land retired' = \emptyset \\
  proven' = \emptyset \land fileOwned' = \emptyset \\
  complete' = complete \\
  remoteAgents' = remoteAgents \land marked' = marked \\
  remoteRes' = remoteRes \land attached' = attached
\end{schema}

\begin{schema}{CrashAfterAgentCreate}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  agent? \notin remoteAgents \\
  remoteAgents' = remoteAgents \cup \{agent?\} \\
  marked' = marked \cup \{agent?\} \\
  attached' = attached \cup \{agent? \mapsto \emptyset\} \\
  active' = active \land building' = building \land retired' = retired \\
  proven' = proven \land complete' = complete \land fileOwned' = fileOwned \\
  remoteRes' = remoteRes
\end{schema}

\begin{schema}{CrashAfterResourceCreate}
  \Delta Lifecycle \\
  res? : RESID
\where
  res? \notin remoteRes \\
  remoteRes' = remoteRes \cup \{res?\} \\
  active' = active \land building' = building \land retired' = retired \\
  proven' = proven \land complete' = complete \land fileOwned' = fileOwned \\
  remoteAgents' = remoteAgents \land marked' = marked \\
  attached' = attached
\end{schema}

\subsection{Sweep}

A sweep is a person's act. It deletes one marked agent the file does not
record, chosen by the person from the listing, together with the resources
that agent lists. It never reaches a recorded agent, an unmarked agent, or a
resource no marked agent lists.

\begin{schema}{SweepMarked}
  \Delta Lifecycle \\
  agent? : AGENTID
\where
  agent? \in marked \setminus (active \cup building \cup retired) \\
  remoteAgents' = remoteAgents \setminus \{agent?\} \\
  marked' = marked \setminus \{agent?\} \\
  complete' = complete \setminus \{agent?\} \\
  attached' = \{agent?\} \ndres attached \\
  remoteRes' = remoteRes \setminus attached~agent? \\
  active' = active \land building' = building \land retired' = retired \\
  proven' = proven \land fileOwned' = fileOwned
\end{schema}

\begin{schema}{ListOrphanResources}
  \Xi Lifecycle \\
  orphans! : \power RESID
\where
  orphans! = remoteRes \setminus \bigcup (\ran attached)
\end{schema}

\texttt{ListOrphanResources} only reports. Deleting an orphan resource is the
person's act, by identifier, because a resource alone does not show who
created it.
